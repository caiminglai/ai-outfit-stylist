专属于中国人的穿衣量化系统 — 它是怎么造出来的

一句话：把「好看」拆成能测的量，再用本地规则与确定性模板解释它；量不到的那一维，就明写「没量到」， 不拿一个猜出来的数冒充分数。核心推荐不是自研大模型，也没有在线模型训练。

01为什么非要"量化"

形象建议这件事，市面上有两种做法：一种是纯主观的审美表达，一种是查黄历式的"你命里缺火"。我们两种都不满足。

主观表达没法复用，今天说的和明天说的可以完全相反；命理推出来的颜色，换个体系就是另一套答案。 所以这个项目从第一天起就只做一件事：把每一项判断落到"从哪来、怎么算、能复算"三格里。 能落到国标或论文的，先核对原文与适用条件；落不到或无法核实的，就承认它是行业经验、另一套体系或未核实来源， 并且在同一条建议上打上依据标签。标签说明依据类型，不自动证明某条审美结论。

02整条管线：五段，一段都不许跳

① 采集表单 + 衣橱 + 穿搭日记 + 拍照取色（图不出设备）
② 量化色名→Lab、尺寸→松量、体感温度→厚薄档
③ 规则匹配378 条静态种子规则按条件命中，出"规则基础分"
④ 确定排序三维分 × 权重，再叠有界偏好乘子与协同过滤乘子
⑤ 模板交付Top N 名单 + 每一维的读数 + 本地确定性文案 + 依据标签

第 ② 段是这套系统的命门：口语颜色必须先落到一个可复算的坐标。顾客写"雾霾蓝"， 系统不猜"大概是蓝色系"，而是查内部色名词表拿到一组 Lab 值，再用国标色差公式算它和他的肤色距离多远。

03四层处理，各管一段

层 吃什么 吐什么 依据边界
色彩量化 色名词表 232 条主名 + 42 组同义族；肤色取色（连续 Lab，不是"你是冷皮"） 色差 CIEDE2000 距离、色相-和谐角、色族归属、明度族 A 色差计算可对应 GB/T 7921-2008；C 色名到 Lab 的取值仍是产品词表
版型映射 身高体重 + 实测四围（选填）+ 衣橱里这件衣服的版型档 松量区间、合身度分、覆盖率与打折因子 A 人体测量方法；C 松量与合身判定线是产品参考
数据采集 两把星（好看/合身）、穿搭日记（日期/场合/城市/体感）、场合词表 三维分快照 + 可回流的样本行 不称科学，只是把经验变成能算的数
协同过滤 和你体型/肤色相近的人群，他们打过的星 第三路信号：同类人偏好乘子 C 行业通行做法，无公开检验

最终分不是三个数平均成一个总分，而是分层结论：规则基础分、色彩贴合分、廓形贴合分各自出账， 页面上一句"综合排序分 15.9/100 · 规则基础分 31（没量全 ⇒ 按可信度打折，乘 0.64）"， 每个数都能倒推回它是哪一维给的。

04依据分四档，标签不等于审美结论

分档由 backend/services/evidenceLevels.js 统一给出，未标注的规则按 C 对待；每条规则仍须说明来源和适用条件。

A 国标/国际标准 可对应的量化口径：色差公式 GB/T 7921-2008、人体测量方法 GB/T 16160-2017。 这些标准只给计算、尺寸与测量方法，本身不含"好不好看"的判据。

B 公开研究 有公开研究出处的规则，必须逐条说明研究对象、样本与结论边界； 不能把健康阈值、图形实验或另一类人群的结论直接套成衣着审美规律。

C 行业体系/经验 四季·十二型色彩、Kibbe 风格型、场合着装、体型五分类等产品规则。 可作风格偏好，不能称客观规律；权重与判定线未完成回归标定。

D 命理体系 八字五行喜用神推出来的颜色与材质。它与前三档不同源， 所以单独一栏展示，不混进"分析结果"里。

第三方标准或研究的完整公开出处若未独立核实，就不在公开页把它写成确定结论；代码中的来源标记也不等于已经完成核验。

05三条硬规矩，写在代码里而不是写在宣传里

  1. 缺测不出分。量不到的那一维直接留空，⛔ 不拿默认值兜底。没量全就按比例打折并写明乘子， 而不是假装那一维也算过了。
  2. 推断不许冒充量化。从文案和面料推出来的版型，话术只能写"按描述推断"， ⛔ 不写"量化了你的体型"；从别人衣橱借来的颜色，⛔ 不写"系统识别出你的上衣是驼色"。
  3. 样本为零时一句都不吹。协同过滤这条路的读数，在没有可比样本时恒等于 1（不加成也不减分）， 前端那行"和你相似的人"整块不出现，⛔ 不写"暂未生效"冒充已有结论。

06反馈如何回流（不是自动训练）

打星好看 / 合身，各 1~5；只打星不点👍也算一条样本
存快照把打分那一刻的三维分一起存下来，作为离线回归的自变量
离线复算人工运行回归脚本；样本不够或快照不齐就拒绝出权重
偏好排序按本人日记与反馈形成有界乘子；样本不足时乘子为 1
当前没有在线模型训练或自动学习。排序权重与阈值仍是产品参考值；偏好乘子只按已有样本微调， 协同过滤也只在同组样本达到门槛后生效。这里不依据运行库行数宣称"已经有真数据在转"， 是否生效以对应部署的可复算记录为准。

1,879条输出动作

规则数来自 backend/db/seed/rules*.json，色名与别名来自 backend/services/color/vocab.js； 这是源码与种子口径，不是运行库现量。数据表数、业务行数、用户数与反馈量随部署变化，不在公开页冒充实时统计。 3D PMX 人物只是展厅展示层，不是试穿模型，也不参与推荐；第三方模型不进公开仓库，部署者须另行确认授权。

08它是怎么交付给一个人的

展厅里有两条入口：门店快速模式（现场服务，少填快算，数据可同步可删除）与 个人深度模式（完整档案 + 衣橱/化妆品/配饰三柜 + 跨柜联动）。 报告页里每一条建议都带四样东西：排名分、依据标签、"为什么推荐这个"、以及"这条建议准吗"的反馈口—— 反馈随时可以撤回，撤了就当没评过。

付费这一环走的是"付款即交付"：到账事实认两笔账（在线订单号，或人工确认过的付款凭证）， 一笔到账换一份细账，按单号幂等，重复点进来读的是同一份，⛔ 不会重复计费； 两张账在同一条读法里各算各的，⛔ 不相加。

09照片与档案：保存、访问、删除

  • 上传即私有保存。试穿人物图与服装图会保存到服务器并登记所有权；非公开文件只能通过有效 HMAC 签名 URL 读取， 默认有效期一小时，匿名直链不能访问。浏览器本地肤色取色是另一条路径，照片不出设备。
  • 外部试穿不是当前已开通能力。仅当部署启用外部试穿时，才会把完成试穿所需的人物与服装图片提供给外部服务； 未配置或未生成效果时返回人物原图并标记 degraded。异步 POST /api/tryon 仍返回 501， 自动面容识别 POST /api/analysis/face 也返回 501。
  • 删档分两步，保留项明说。账号入口只删服务端认证账号拥有的业务记录，不凭门店号码代删；门店数据由持有者在门店报告页单独删除。 两个入口都保留支付凭证、已付费报告及其复读依据，且保留的报告不会再被当作旧表单回填。业务记录提交后，仅物理删除没有其他记录引用的本人上传文件； 文件或台账清理失败时账号入口返回 207，可重试 DELETE /api/analysis/archive，不会把部分成功说成全部删净。

10接下来做什么

  • 把已经铺好的采集通路喂上真样本，让权重回归第一次有自变量可算；
  • 继续校准现有分层：关系色解析、版型推断、天气与场合规则，以及偏好和协同过滤的样本门槛；
  • 把"专属"落到中文语境：更多中文口语色名、本土场合（如婚礼宴席、通勤地铁）的规则，并逐条补可核实出处。

所有口径变更都按"先出输入输出规范、再动代码"的顺序记录在仓库的 docs/依据/ 里。 原文、许可或公开出处无法核实的，明确标为未核实，不包装成已证实的科学结论。

这页讲的每一条都可以被追问：静态数字来自源码与种子，运行效果以对应部署的复算记录为准； 档位来自规则库的 evidence_level，措辞受三条硬规矩约束。发现哪句说大了，是我们的 bug，直接回展厅首页提反馈。
