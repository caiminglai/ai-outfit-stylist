专属于中国人的穿衣量化系统 — 它是怎么造出来的

一句话：把「好看」拆成能量出来的量，再用有出处的规则去解释它；量不到的那一维，就明写「没量到」， 不拿一个猜出来的数冒充分数。

01为什么非要"量化"

形象建议这件事，市面上有两种做法：一种是纯主观的审美表达，一种是查黄历式的"你命里缺火"。我们两种都不满足。

主观表达没法复用，今天说的和明天说的可以完全相反；命理推出来的颜色，换个体系就是另一套答案。 所以这个项目从第一天起就只做一件事：把每一项判断落到"从哪来、怎么算、能复算"三格里。 能落到国标或论文的，就写清楚标准号；落不到的，就承认它是行业经验或另一套体系， 并且在同一条建议上打上依据标签——顾客不需要相信我们，他可以点开看这句话的出处硬不硬。

02整条管线：五段，一段都不许跳

① 采集表单 + 衣橱 + 穿搭日记 + 拍照取色（图不出设备）
② 量化色名→Lab、尺寸→松量、体感温度→厚薄档
③ 规则匹配378 条规则组按条件命中，出"规则基础分"
④ 算法排序三维分 × 权重，再叠偏好乘子与协同过滤
⑤ 出账交付Top N 名单 + 每一维的读数 + 依据标签

第 ② 段是这套系统的命门：口语颜色必须先落到一个可复算的坐标。顾客写"雾霾蓝"， 系统不猜"大概是蓝色系"，而是查内部色名词表拿到一组 Lab 值，再用国标色差公式算它和他的肤色距离多远。

03四条算法轴，各管一段

轴 吃什么 吐什么 现在多硬
色彩量化 色名词表 232 条主名 + 42 组同义族；肤色取色（连续 Lab，不是"你是冷皮"） 色差 CIEDE2000 距离、色相-和谐角、色族归属、明度族 A 公式与测量口径有国标/国际标准
版型映射 身高体重 + 实测四围（选填）+ 衣橱里这件衣服的版型档 松量区间、合身度分、覆盖率与打折因子 B 量级对得上国标人体尺寸，判定线是产品参考
数据采集 两把星（好看/合身）、穿搭日记（日期/场合/城市/体感）、场合词表 三维分快照 + 可回流的样本行 不称科学，只是把经验变成能算的数
协同过滤 和你体型/肤色相近的人群，他们打过的星 第三路信号：同类人偏好乘子 C 行业通行做法，无公开检验

最终分不是三个数平均成一个总分，而是分层结论：规则基础分、色彩贴合分、廓形贴合分各自出账， 页面上一句"综合排序分 15.9/100 · 规则基础分 31（没量全 ⇒ 按可信度打折，乘 0.64）"， 每个数都能倒推回它是哪一维给的。

04依据分四档，只有前两档能叫"科学"

这套分档不是营销话术，是代码里的唯一实现处（backend/services/evidenceLevels.js），未标注的规则一律按 C 对待。

A 国标/国际标准 现行标准里能对上的量化口径：色差公式 GB/T 7921-2008、人体测量方法 GB/T 16160-2017。 注意——这些标准只给尺寸与测量方法，本身不含"好不好看"的判据。

B 学术实证 有同行评议论文与可复算公式：CIEDE2000、Schloss & Palmer 的色相相似-和谐回归、WHO 腰臀比阈值。 有争议的我们照写（ Singh 1993 的美学侧结论存在 BMI 混淆）。

C 行业体系/经验 四季·十二型色彩、Kibbe 风格型、场合着装、体型五分类。可以做风格偏好， 不能称客观规律；2011 年一项 n=200 的研究还发现各套季型系统判型互不一致。

D 命理体系 八字五行喜用神推出来的颜色与材质。它与前三档不同源， 所以在页面上单独一栏展示，不混进"分析结果"里。

05三条硬规矩，写在代码里而不是写在宣传里

  1. 缺测不出分。量不到的那一维直接留空，⛔ 不拿默认值兜底。没量全就按比例打折并写明乘子， 而不是假装那一维也算过了。
  2. 推断不许冒充量化。从文案和面料推出来的版型，话术只能写"按描述推断"， ⛔ 不写"量化了你的体型"；从别人衣橱借来的颜色，⛔ 不写"系统识别出你的上衣是驼色"。
  3. 样本为零时一句都不吹。协同过滤这条路的读数，在没有可比样本时恒等于 1（不加成也不减分）， 前端那行"和你相似的人"整块不出现，⛔ 不写"暂未生效"冒充已有结论。

06自我学习怎么闭环

打星好看 / 合身，各 1~5；只打星不点👍也算一条样本
存快照把打分那一刻的三维分一起存下来，当回归的自变量
重算权重离线最小二乘回归，样本不够就沿用现值并说明为什么
出乘子你的偏好按可信度打折后乘进排序，⛔ 不改那三个权重本身
如实说一句：这个闭环现在还没有真数据在转。下面的库底数就是证据——反馈表目前是 0 行， 所以线上跑的权重仍是建档时手拍的初值，偏好乘子对所有人都等于 1。 系统把通路铺好了，等的是真实用户走进来。这不是缺陷，是它的真实进度。

08它是怎么交付给一个人的

展厅里有两条入口：门店快速模式（现场服务，少填快算，数据可同步可删除）与 个人深度模式（完整档案 + 衣橱/化妆品/配饰三柜 + 跨柜联动）。 报告页里每一条建议都带四样东西：排名分、依据标签、"为什么推荐这个"、以及"这条建议准吗"的反馈口—— 反馈随时可以撤回，撤了就当没评过。

付费这一环走的是"付款即交付"：到账事实认两笔账（在线订单号，或人工确认过的付款凭证）， 一笔到账换一份细账，按单号幂等，重复点进来读的是同一份，⛔ 不会重复计费； 两张账在同一条读法里各算各的，⛔ 不相加。

09接下来做什么

  • 把已经铺好的采集通路喂上真样本，让权重回归第一次有自变量可算；
  • 继续磨四条轴：关系色解析、版型推断层、天气与场合的量化、协同过滤的第二/三类信号；
  • 把"专属"落到 Chinese-specific 的那一半：更多中文口语色名、中国人体尺寸分布的档位、本土场合（如婚礼宴席、通勤地铁）的规则。

所有口径变更都按"先出输入输出规范、再动代码"的顺序记录在仓库的 docs/依据/ 里， 每条依据要能在本机找到原文（标准号 + 年号 + 官方入口），查不到就写明搜过的关键词。

这页讲的每一条都可以被追问：数字来自数据库现量，档位来自规则库的 evidence_level， 措辞受三条硬规矩约束。发现哪句说大了，是我们的 bug，直接回展厅首页提反馈。
