这门课怎么用

三条规矩，先看完再上课。

一、全部教材就是你自己的项目。 每一课都指着仓库里的真文件和真行号（蓝底那种就是行号，VSCode 里按 Ctrl＋G 输行号直接跳）。我不给你玩具例子，学完你就能读懂自己这套东西。

二、一课 30 到 50 分钟，别贪。 每课最后一栏是「过了吗」，勾上就打卡，进度条存在你这台浏览器里（刷新不丢，换浏览器不带走）。 三课连着学不如一天一课——编程是手感活。

三、命令一律复制去跑，别手敲。 每个灰底代码块右上角有「复制」。跑之前看一眼它在哪个目录：写 cd E:/website/3.personal-image-ai/backend 的就在后端目录跑。⛔ 任何一课都不许碰服务器，也不许对 backend/db/styleai.db 写。

学到什么程度算毕业：你能自己做完一轮小改动——说清改哪儿、改完跑得绿、真打开看一眼、写得了台账、按自己的手提交。 不需要你能从零写出推荐引擎，那一层是我和 AI 干的活。

第 2 课 · 一条请求的旅行

目标：从浏览器地址栏一路看到数据库门口。教材是 backend/routes/weather.js（68 行，全站最短的路由）加 backend/server.js:160 那几行接线。

五个必看的落点

位置 干什么 人话
backend/routes/weather.js:5-8 require 把要用的东西请进来 先声明"我要用谁"，后面才敢用
backend/routes/weather.js:10 express.Router() 这一堆网址先装进一个小盒子，最后由 server.js 挂上
backend/routes/weather.js:22-30 router.get('/', ...)：取参数 → 验参数 → await 服务层 → 成功就发 网址对上函数，函数只干三件事：验进、算、发回
backend/routes/weather.js:34-40 catch：照服务层给的 err.status 发错误，没给才发 500 失败也要说清"为什么失败"，不许甩一个含糊的 500
backend/server.js:342 app.use('/admin', adminRoutes)；对照 :160 的 app.use('/api/', apiLimiter) 挂载＝"哪个网址前缀归哪个盒子管"

为什么要写 await。问天气要去敲别人家的门（上游接口），来回要几百毫秒。 不加 await，代码不等它，拿回来的是一个还没装货的空盒子。 记一句：会花时间的动作前面加 await，并且它一定可能在某一刻失败——所以必须包在 try/catch 里。

为什么要 sendSuccess／sendError 两个小函数。看 backend/utils/response.js:14-25：成功永远长成 { success: true, data: ... }，失败永远长成 { success: false, error: { code, message } }。前端只按这一个形状读， 不用每个接口猜一次。统一的返回形状，是多人／多页面项目不死掉的底线。

这一路里有道闸。backend/server.js:125-126 写着 15 分钟窗口、每 IP 100 次——顾客走的那条 /api 前缀全在这道闸后面。 而后台的 /admin/api/* 不吃这道闸，它有自己的 60 秒 600 次 （backend/routes/admin.js:23-31）。所以你写脚本狂刷 /api 时，屏幕上会出现「请求过于频繁」——十有八九是你自己刷的， 先去数自己的探针，别去找 bug。

第 3 课 · 数据落在哪：SQL 与那个 .db

目标：能读懂表结构，能自己写一句只读的 SELECT，并且永远分得清"活库"和"副本"。教材是 backend/db/schema.sql（687 行）和 backend/routes/payment.js:47 那一行查询。

三块必读

① 开头那三行开关很关键。backend/db/schema.sql:7-9 开了 WAL、synchronous=NORMAL、外键。WAL 的意思：写入先进 styleai.db-wal 这个日志，再慢慢合回主库。所以你在 backend/db/ 里看到 .db、.db-wal、.db-shm 三个是一套，⛔ 不能在服务还开着的时候乱删后两个。

② 一张表就是一张 Excel。比如 backend/db/schema.sql:16-23 的 users：id 自增主键（自己长号），session_id 唯一且必填（游客身份），phone 唯一但可空（没注册就没有）， created_at 默认取当前时间。读懂这几列，你就读懂了"顾客"在你系统里到底是什么。

③ 查库就一行，但那个 ? 是命。 backend/routes/payment.js:47 是： 

const row = db.prepare('SELECT value FROM app_settings WHERE key = ?').get(PRICE_KEY)

prepare 写好句子，? 留坑，get 填坑并取一行。 ⛔ 永远不要把用户的输入用字符串拼进 SQL——那一句拼错就是"库里所有表任人拿走"（术语叫 SQL 注入）。这一套用的是 better-sqlite3，它是同步的：不用 await，调用完立刻拿到结果，这也是它选它的原因。

现在就做：只读副本上查一次（20 分钟）

⛔ 全程不碰 backend/db/styleai.db 本体。它还被 git 的 skip-worktree 钉住（提交不进版本，发布另有自检脚本），你在上面随手一写， 就等于随手改了线上业务数据。先复制一份到仓外。 
mkdir -p E:/website/files/learn-l3
cp E:/website/3.personal-image-ai/backend/db/styleai.db E:/website/files/learn-l3/copy.db
cd E:/website/3.personal-image-ai/backend
node -e "const D=require('better-sqlite3')('E:/website/files/learn-l3/copy.db',{readonly:true});console.log(D.prepare(\"SELECT name FROM sqlite_master WHERE type='table' ORDER BY name\").all().length+' 张表');console.log(D.prepare('SELECT key,value FROM app_settings ORDER BY key').all())"

看到表数与 app_settings 里那些键值（收款金额就在里面），这一课就通了。 {readonly:true} 那一串是保险丝：写操作会当场报错，比事后道歉便宜。请把它当习惯。

第 4 课 · 界面为什么动

目标：看懂前端三件事——数据怎么进来、界面怎么画、请求怎么发出去。教材是 app/src/components/ErrorBoundary.tsx（90 行）和 app/src/api/core.ts:210 那一层。

⛔ 别从展厅开始。app/src/pages/ExhibitionHall.tsx 拆前 1,421 行（尺子＝git show HEAD 那份 wc -l），11-03 拆分轮瘦到 483 行，部件在 app/src/pages/exhibition/；它里面还有 3D 模型， 仍是最难的那份、不是入门材料。前端现在 81 个 .ts/.tsx（不含测试），从最小的那个读起。

三句话讲完 React

  1. 数据进来。组件的输入叫 props（父组件塞给你的参数）和自己记的东西叫 state（状态）。看 app/src/components/ErrorBoundary.tsx:3-11： interface Props 写"别人要给我什么"，interface State 写"我自己记什么"。
  2. 按数据画界面。app/src/components/ErrorBoundary.tsx:41 的 render() 只做一件事：状态里 hasError 是真的就画兜底，是假的就是正常孩子。
  3. 数据一变，画面重画。 app/src/components/ErrorBoundary.tsx:37-39 那颗"重试"按钮里 this.setState({ hasError: false })——注意它没有去改 HTML，它只改状态，画面自己跟着变。这是前端和后台最不一样的地方：你不操纵界面，你操纵数据。

顺带看懂 TypeScript：那个问号 fallback?: React.ReactNode 意思是"这颗可以不填"。类型就是填表说明——写清楚要什么， 少填、填错，构建阶段就报错（这也是为什么 app/package.json:8 的 build 是 tsc -b && vite build 两段式：先体检再造货）。

前端怎么发请求

全项目发请求的手都在 app/src/api/core.ts（292 行；11-03 拆分轮起 app/src/api.ts 只剩 98 行转发名单，正文按领域分成 app/src/api/ 那 12 份）。核心那一行是 app/src/api/core.ts:210：await fetch(url, { ...options, signal: controller.signal })。那个 signal 是超时用的刹车—— 不装刹车，后端一旦卡住，顾客屏幕上就永远转圈，连报错都不给。

还有一条口径要你记住，它写在我给你写的那页教材旁边： backend/routes/weather.js:52-58——上游没给体感温度就回 502 说破，⛔ 不许前端自己补一个档。第 1 课 L42 是同一句品德的第二遍：量不到就说不，前端后端都不许编。

现在就做：本地起前端，改一句文案（20 分钟）

cd E:/website/3.personal-image-ai/app
npm run dev

它回 VITE v7.3.6 ready in 449 ms 和 Local: http://127.0.0.1:5173/（这读数是我刚跑的）。开浏览器进 5173（不是 5000）。

  1. 为什么 5173 能用到后端？因为 app/vite.config.ts:51-58 配了代理：/api、/admin、/static 等前缀统统转给 localhost:5000。前端开发跑 5173，后端还是那个容器。

第 5 课 · 测试是合同，不是形式

目标：会读一份测试，并自己写出第一条能跑的测试。教材是 backend/test/bmi.test.js（70 行，全站最短）。

读四段

位置 这一手在教你什么
backend/test/bmi.test.js:17-31 用 for 把 8 组坏值排着队喂进去（0、负数、null、'abc'、空串、Infinity）。一条测试能覆盖一批输入， 这就是"重复"的价值。

第 6 课 · 四道门：改完凭什么敢说没坏

目标：一轮改动之后，自己把门禁跑一遍，并且看得懂红。教材是两份 package.json 的 scripts。

这四道门各管什么

命令（在 backend/ 里） 管什么 红了怎么读
npm run format:check prettier 排版，只扫 **/*.js（见 backend/package.json:11） 列出的文件名＝格式不对，不是逻辑错。跑 npm run format 让它自己排好，再 check 一次。
npm run lint eslint 习惯（backend/package.json:12） 只有 error 会卡住；warning 不卡（11-03 04:5x 现量 0 error／58 warning；尺子＝npm run lint 末尾那行，条数每轮都会变，读数带时刻）。读规则名，别看条数吓人。
npm test node --test "test/*.test.js"（backend/package.json:14）——本仓是 Node 自带测试，不是 vitest 看末尾 pass/fail 两行，再往上翻第一个 ✖；那一句后面通常跟着你写的"人话说明"。
npm run build（在 app/ 里） tsc -b && vite build（app/package.json:8）：先类型体检，再打包 类型错会指出文件与行；⚠️ 别用 tsc --noEmit，见下。
三个真坑，都是这个项目自己踩出来的。 ① tsc --noEmit 会假通过：前端根 tsconfig 是"solution 型"（只管引用别的 tsconfig），--noEmit 对它回 0 却什么都没检查。只认 tsc -b（现成脚本是 app/package.json:11 的 typecheck）。 ② 管道会吞退出码：npm test | tail -3 之后的 $? 是 tail 的，永远 0——红的会被读成绿的。要看退出码就别接管道，把输出重定向到文件再看 $?。③ prettier 只管 **/*.js：HTML／CSS／后台 JS 根本不在射程内，"格式门绿了"不等于你改的那片被检查过。

第 8 课 · git：三个位置与一次提交

目标：不再怕 git。先把"东西在哪三个位置"讲清，再练只读三连，最后练一次写。

三个位置，一张嘴说得清

位置 是什么 对应命令
工作区 你盘上正在编辑的这些文件本身 你 Ctrl＋S 就改了它
暂存区（索引） "这次提交我要带上哪些改动"的购物车 git add -u 装进车
HEAD／仓库 已经落档的历史，一次提交一格 git commit 落档；git log 翻档

为什么非要中间那个购物车：因为你可能同时改了 12 个文件，而这一次只想交其中 11 个。这个项目就有一条永远不进车的： backend/db/styleai.db（运行时库，另有一条 skip-worktree 的钉子钉着它）。

只读三连：先练这个，永远安全

cd E:/website/3.personal-image-ai
git status --porcelain
git diff --stat
git log --oneline -3

三条都不改任何东西。--porcelain 是给机器读的一行一个文件（M 是改过、?? 是还没进版本的新文件）；diff --stat 告诉你每个文件加了几行删了几行；log --oneline 是历史。养成习惯：动手前后各跑一次这三条，你会立刻知道自己有没有把事情弄干净。

一次真实的提交（照这个形状记）

git add -u
git restore --staged backend/db/styleai.db
git add backend/templates/learn-to-code.html
git commit -F E:/website/files/commit-msg.txt
git status --porcelain
git log --oneline -1
  • add -u 只装"已跟踪且改过"的，不会把杂物带进去；新文件必须点名 git add。
  • 第二行是关键：restore --staged 只把它从购物车拿出来，盘上那个文件一个字没动。⛔ 千万别对它用 checkout -- 或 reset --hard——那是"用仓库版本覆盖你盘上的运行库"，等于把真实业务数据抹掉。
  • 中文提交说明走 -F 文件：直接 -m "中文..." 在这台机器上会变乱码（GBK 的坑），把话写进一个文件再让 git 读，就不会出事。
还有个计数坑：git status --porcelain 遇到中文文件名会输出成 "docs/\344\276\235..." 这种八进制转义，还把引号带上。你要用它数分母，就得先算上这两层，否则会报成 0。 ⛔ 不要为了好看去关 core.quotepath 之外的配置——这条我提醒你，改配置由你自己决定。

一条探针长什么样

所谓"探针"就是一个只读的小脚本，三段：取什么 → 算什么 → 打出来。就这么多。

// 数一下后端有多少个 js 文件、总共多少行
const fs = require('fs')
const path = require('path')
let files = 0
let lines = 0
;(function walk(dir) {
  for (const e of fs.readdirSync(dir, { withFileTypes: true })) {
    if (['node_modules', 'dist', 'vendor', '.git'].includes(e.name)) continue
    const q = path.join(dir, e.name)
    if (e.isDirectory()) walk(q)
    else if (e.name.endsWith('.js')) {
      files++
      lines += fs.readFileSync(q, 'utf8').split('\n').length
    }
  }
})('E:/website/3.personal-image-ai/backend')
console.log('文件', files, '行', lines)

跑法：node E:/website/files/我的探针.cjs。它不连库、不发请求、不写文件， 只读——这就是安全边界。更常见的量法不用写脚本，一条命令就够： 

cd E:/website/3.personal-image-ai
find backend -name '*.js' -not -path '*/node_modules/*' -not -path '*/vendor/*' -print0 | xargs -0 wc -l | tail -1
find app/src \( -name '*.ts' -o -name '*.tsx' \) -print0 | xargs -0 wc -l | tail -1
ls backend/test/*.test.js | wc -l

我刚才跑的读数（10-22 晚上，含这份教程页自己那份测试）：后端 54,354 行、前端 app/src 14,015 行、测试文件 56 份。你跑一遍，数字以你那次为准—— 我这条只是告诉你"应该长这样"，不是让你抄我的数。

三条纪律（我在这项目上错过太多次，写成规矩）

  1. 报数必须带尺子。同一个"多少"能有好几种量法（含不含 test/？含不含 vendor/？按文件数还是按行数？按盘上还是按 HEAD？）。写数的时候顺手把命令贴在旁边，下次能重算。
  2. 判"没有"要更严。搜不到不等于没有：文件名可能是中文、可能有区间缩写（oa1~oa3 那种要展开再搜）、工具可能静默失效。写"没有"之前，先证明"我的搜索确实能读到东西"（拿一个已知在的东西同批搜一遍）。
  3. 用完就清。临时件写进 E:/website/站3产生临时文件/ 这类仓外目录，用完当场删掉并报一句"删前几件、删后几件"。仓库里 ?? 长期只留交付物，别人（包括未来的你）才看得清哪些是货、哪些是垃圾。

你提问的质量决定你拿回的东西的质量。四段话，照抄形状：

反面样子（一句话就能看出为什么得不到好答案）："页面打不开，帮我看看"。⇒ 哪个页面、什么地址、报什么、你点过什么，全空。
