## 一、第一步：三件改动逐件交代

### 1.1 提高算法权重（`recommendEngine.js:501`）

```js
const RANK_WEIGHTS = { rule: 0.1, color: 0.45, body: 0.45 }   // 改前 { rule: 0.2, color: 0.4, body: 0.4 }
```

权重和仍是 1.000（测试 `recommendEngine.test.js` 里那条"三个权重该归一"钉住了）。

**这一件单独做几乎没用，实测出来的**：`rankDims` 走的是"按在场权重归一化"（`:590-602`），一维独苗时那维会被约成满分，所以把 rule 从 0.2 压到 0.1 对"只有规则分出分"的候选**只多挨一点覆盖率折扣**：coverage 从 0.2 掉到 0.1 ⇒ 合成因子 0.68→0.64。改前榜首 68.0 分，光改权重只变成 64.0，还是榜首。这就是为什么必须配后两件。

### 1.2 算法缺席惩罚（常量 `:548`，落在 `rankDims` `:624-630`）

```js
const RANK_ALGO_ABSENCE_PENALTY = 0.8
// rankDims 内：
const algoMissing = dims.filter((d) => d.key === 'color' || d.key === 'body')
                         .filter((d) => !(d.score != null && d.weight > 0)).length
const algoPenalty = src.isRule && algoMissing > 0 ? RANK_ALGO_ABSENCE_PENALTY : 1
score = round(raw × factor × algoPenalty × 10) / 10
```

三条口径我替你写死了，都写在 `:534-547` 的注释里，理由是它们各自都能毁掉一件事：

1. **只打规则来源的候选**（`src.isRule`）。你原话的前提是"对于纯规则命中的条目"，我把作用域就锁在这一句的主语上。衣橱里量出来的那些行**不吃**这条惩罚——它们的缺测已经被 `topFitBody.js:173` 的 `COVERAGE_PENALTY` 在身体层乘过一次、又被排序侧的 coverage 折扣管过一次，再叠一个 0.8 就是**同一件事收三回钱**，而且罚的正是我们最想让用户填的那格数据（本项目反复在清这一类病灶，见第三阶段那条"覆盖率惩罚只在身体层乘一次"的测试）。
2. **缺一维与缺两维都只乘一次**，不搞 0.8×0.8。这条惩罚表达的是"这条推荐没经过算法"这一个事实。
3. **与覆盖率折扣叠乘**（不互斥、不取大）。后果：纯规则条目合成因子 = 0.64 × 0.8 = **0.512**。这是刻意的，也是本轮最需要你看一眼的数字——它把"一个字都没量过"的条目从 68 分档压到 51.2 分档。

出账跟着改了：每条候选的 `rank` 现在多带 `algo_missing`（缺几维）、`algo_penalty`（乘了多少）、`algo_present`（有没有算法分），报告与回归脚本都能拆账，不留"只有一个总分"的黑箱。

### 1.3 强制算法在场（常量 `:563`，逻辑在 `rankAndTruncate` `:681-735`）

```js
const RANK_MIN_ALGO_IN_TOP = 2
// 名单取完 Top 8 后：在场的不足 2 条 ⇒ 从落选池按算法分降序补，
// 同时从名单末尾踢掉同数量的算法缺席条目（踢的是分最低的那几条）
```

四个设计决定，都是"不这么做就会出假东西"：

- **补进来的按它自己的综合分排位次，不插队到榜首**。把一条 40 分的东西抬到第一，只是把"抛硬币"换成"拍脑袋"。它保证的是"进前 8 被看见"。
- **踢谁补谁是决定性的**：落选池按 `算法分降序 → rankCmp` 选，名单内按 `rankCmp` 末尾踢。同一个人算两次，名单一字不差（测试第三条钉住了）。
- **凑不出就不硬塞**。`⛔` 写在 `:555-562`。池子里只有 1 条带算法分时，前 8 就是 1 条，出账如实记 `in_top:1 / in_pool:1`，绝不捞一条 `null` 分的条目进来凑数——那会让报告上出现"0 分的推荐"。
- 为了把这件事测出来，我把 `rankAndTruncate` 单独导出了（`:1043`，纯函数、不碰库）。这同时是还蓝图里 D5 那条债（"测试是函数级为主"）的一小步。

出账：`result._computed.ranking` 新增 `algo_absence_penalty`、`min_algo_in_top`、`algo:{required,in_top,forced_in,in_pool,candidates}`，`note` 文案同步带上惩罚与下限（后台只显示权重的话，会看不出分数是被谁压下去的）。

还有一件**必须先纠正你的指令再动手**的事：同义词库不能按"驼色＝卡其色＝棕色"这么合并。

顺带一个便宜发现：表里现在是 `焦糖` 而不是 `焦糖色`、`咖啡棕` 而不是 `咖啡色`、`米白/奶油白` 而不是 `米色`、`奶杏色` 而不是 `杏色`。**加一层"色名后缀归一"（剥掉尾缀"色"再查表）就能把那 5 条带具体色词的补上**，比手工扩 150 个键便宜得多。
