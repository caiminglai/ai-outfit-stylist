## 一、本轮范围（对齐你 2026-10-21 那句"第一步：优化穿搭日记"）

做三件事，按序：

1. **日记补三列并接通写读与前端**（§二～§四＋§七）：哪天穿的、体感几度、哪一档天气。这是"根据天气学偏好"的唯一前置——没有它，后面每一层都只能拿到"提交时间"。
2. **隐性偏好学习从两轴升到四轴**（§五）：温度档→厚薄档、复穿次数、场合升档，加上既有的色族与版型。这就是"自动学习隐性偏好"在本项目里的**全部**可实现含义；⛔ 它不是机器学习，也不训练任何模型（措辞红线见 §九）。
3. **协同过滤开第二类信号**（§六）：把"同组人在这个场合/温度档下常穿哪一档"接进来，与第九阶段那把星级共用同一套收缩公式与同一个乘子界。

明确不做（省下来的是下一轮的钱）：

- ⛔ 不做"根据天气自动改推荐名单"（那是把 `allowed_seasons` 变成硬过滤，等于用一个外部数据源删掉候选，跟"缺测不出分"打架）；本轮天气**只当乘子的输入与日记的一格存档**。
- ⛔ 不做自动定位（IP 定位、浏览器 geolocation 都要新权限与新失败面）；用户选城市，选不到就手选档。
- ⛔ 不动 `feedback_events` 与 `item_feedback` 两张表的任何列，⛔ 不进 `rankDims` 三维出账，⛔ 不进回归脚本自变量（`17` §4.3 那三条"不许"照抄生效）。
- ⛔ 不给日记加图片、加"今天心情"、加社交分享——那不是量化，是功能堆。

## 三、词表与校验契约（写入口的唯一一把尺子）

1. **五档词表只留一份**。`services/weatherService.js` 新增导出 `WEATHER_LEVELS = ['寒冷','偏凉','舒适','偏热','炎热']` 与 `levelFromFeelsLike(t)`；既有 `buildTemperatureProfile`（`:165`）**改成调用 `levelFromFeelsLike`**，⛔ 不许在 `routes/wardrobe.js` 或前端再抄一份阈值。阈值原样沿用现网那五刀（≤5／≤14／≤24／≤30／其余），因为它们已经在话术里跑着，改了会让"报告说的话"和"库里的档"两套并行。
2. `wear_date`：必须是 10 位 `YYYY-MM-DD`、必须是真实日历日、**不得晚于"今天"（按 `Asia/Shanghai` 判定）**、不得早于 `2015-01-01`（本项目没有意义地早的历史）。给不出合法值 ⇒ **400 说破**，⛔ 不许悄悄落成 NULL 再悄悄用 `created_at` 顶上。
3. `feels_like_c`：有限数、范围 `-60 ~ 60`，越界或非数 ⇒ 400。⛔ 不许把空串 `''` 当 0℃（那是"今天 0 度"，不是"没填"）。
4. `weather_level`：给了就必须 ∈ `WEATHER_LEVELS`，表外词 ⇒ 400（与 `occasion` 同一口径：表外词命不中任何算式，采了白采）。
5. **一致性闸门（本轮新增，最容易被打脸的一条）**：`feels_like_c` 与 `weather_level` **同时给出**时，必须满足 `levelFromFeelsLike(feels_like_c) === weather_level`，否则 **400** 并逐字说破"体感 X℃ 应该算 Y 档"。理由：前端既可能"取今天天气"自动填、又可能用户手选档，两条路各填一半就会造出"30℃ 却写着寒冷"这种永远学不出来的行。⛔ 不许以"用户手选的档优先"名义静默改写任何一格。
6. **`undefined` / `null` / 有值三态**继承 `18` §三：`undefined`＝这格不动（PUT 半更）、`null`＝明确清空、其它＝校验后写入。清空 `weather_level` 时若 `feels_like_c` 还在，允许（温度是事实，档是解释），但读取侧一律**以 `feels_like_c` 现推**（§五 第 2 条）。

## 五、隐性偏好层：从两轴乘子升到四轴（`services/wearPreference.js`）

现状（§〇 第 5 条）只有 `color_family`／`fit_type` 进乘子。本轮加两根、升一根，并把出账轴从 5 扩到 7。

1. **新轴 `warmth`（温度档→厚薄档）**——"你在冷天翻出来穿的那件是厚的还是中的"。
   - 原料：日记行里的 `weather_level`（缺则用 `feels_like_c` 现推，再缺则**这一行不进这一轴**）× 该套 `item_ids` 指向的单品的 `fabric_weight`（薄/中/厚）。

   - 用在哪：仅当**本次推荐请求带了 `weather_level`**（新增可选入参，走 `profile` 透传，与 `occasion` 同一来路 `enriched.occasion` 那一层）且**候选身上取得到 `fabric_weight`** 时才乘；命中该档众数 ⇒ `+LIFT_TOP`，取到但不同档 ⇒ `0`，候选没填厚薄 ⇒ **不乘**（⛔ 不许把"没填"当"不厚"）。

2. **新轴 `reps`（复穿次数）**——"这件衣服你自己反复记了多少天"。这是三层信号里最硬的一条（行为，不是表态）：星是"我觉得"，日记是"我真穿了"。
   - 原料：`wardrobe_outfits.item_ids` 展开后按**单品 id** 计数（跨套累加、同一套内一件只记一次）。
   - 用在哪：只对 `source==='wardrobe'` 的候选生效（只有衣橱候选有可比的 `id`；规则库商品与他的衬衫不是同一件东西）。候选 id 计数 n ⇒ `lift = min(REPS_MAX, REPS_STEP * ln(1+n))`，`REPS_STEP=0.006`、`REPS_MAX=0.03`（⛔ 全部 C 档手拍，标定中；取 ln 是为了"记 40 次"别把总分掀翻）。
   - ⛔ 这一轴**不进** `color_family`/`fit_type` 的计数（那两轴已经天然吃到复穿：一套里每族只记一票、跨套累加，`wearPreference.js:172` 起那个循环现量能证明）。再乘一次就是把同一件事数两遍——本项目最常见的假涨分。
3. **升档 `occasion`**：`multiplier: false → true`，前提由 §〇 第 4 条给（候选带 `occasion_tags`）。命中"你日记里最常记的那个场合"且候选 `occasion_tags` 含它 ⇒ `+LIFT_TOP`；场合标签为空 ⇒ 不乘。规则库那侧候选若取不到 `occasion_tags`（数组为空），这一轴对它**逐条隐身**，不是给它 0 分。
4. **不动的东西**：`MIN_SAMPLES=3`、`[0.95,1.05]`、`+2%/0/−1%` 三档幅度、`factor_ready` 语义、`provenance` 必带"是哪几行算出来的"、⛔ 不进 `rankDims` 三维出账。四根乘子轴合起来仍受 `FACTOR_MIN/MAX` 那道夹紧——**上限不因轴变多而变宽**，这是"偏好盖不过色彩与廓形真分"那句设计意图的唯一护栏。
5. **出账新增**（`result._computed.ranking.preference`，`recommendEngine.js:830`）：`axes` 从 `['color_family','fit_type']` 变四轴、新增 `weather_level_used`（本次请求带来的档，没有就 `null`）、`reps: {counted_items, max_reps}`。⛔ 不许新增一个"偏好总分"字段。

## 六、协同过滤的第二类信号（`services/collabFilter.js`）

第九阶段那一层今天只回答一句话："和你体型相近的人，在这个场合给这件衣服打了几分"（`17` §四）。本轮加第二句：**"和你体型相近的人，在这种天气下常穿哪一档"**。

1. **可比性的真话**（这条必须先说，不然整层是假的）：`item_ids` 指向的是**每个人自己的衣橱行**，两个人各有各的"蓝衬衫"，跨人比 `item_ids` 在语义上不成立。全库唯一能跨人比"同一件衣服"的钥匙是 `user_wardrobe.sku`（第五阶段加的列），本机库现量 **0 行非空**。⇒ 本轮的跨人信号只能是**属性档分布**（色族／厚薄档／版型档），⛔ 不许写"和你身材相近的人也买了这件"。等门店真把 SKU 扫进来那天，才轮到"同一件"那句话（挂 §十 待裁第 2 条）。
2. 实现形状：cohort 沿用 `17` §4.2 那三项（身高＋净胸围＋净肩宽，实测优先、缺格由第五阶段估算顶上）＋本次 `occasion`；在组内把"该成员在**本次温度档**下的日记属性档分布"折成与星级同一形式的收缩分：`shrunk = (n·组内均值 + K_PRIOR·全局均值) / (n + K_PRIOR)`，`n` 换成"组内在这个温度档记过几套日记"。乘子仍 `clamp(1 + AMP·(shrunk − 全局均值)/SPAN, 0.95, 1.05)`，**⛔ 不许开第二个 AMP、第二个上下界**。
3. 两条信号合成：星级与日记分布**各出一个 factor，两个 factor 相乘后再夹紧一次**（不是把两个信号加权成中间值——那是"平均掉互相反对的结论"，本项目第 N 次拒绝）。任一信号样本不足 ⇒ 那一个恰好 1。
4. 三条"不许"逐字继承 `17` §4.3：⛔ 不进 `rankDims`、⛔ 不改 `algo_score_of`、⛔ 不进回归自变量；`COLLAB_FILTER_ENABLED=0` 仍必须让 Top 8 与改前**逐条相同**（有测试钉）。
5. 隐私红线不变：`cohort_size < 3` ⇒ 不出话术、乘子恰好 1；单条日记人／姓名／门店／时间戳一律不出前端。
6. 出账新增 `collab.diary_signal`：`{cohort_diary_sets, temperature_level, attribute}`，`enabled:false` 或无样本时为 `null`（"上线即隐身"这条要读得出来）。
