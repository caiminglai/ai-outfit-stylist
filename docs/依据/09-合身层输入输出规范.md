# 合身层（第 0 层）输入输出规范与判定逻辑

建档：2026-10-09。代码落点 `backend/services/fitSize.js`，由 `services/topFromBody.js` 作为 `topSpec().fit` 的第 0 段调用。
这份文件是这一层的**唯一出处**：字段名、算法、档位、措辞边界都以此为准；改代码必须同轮改这份文件。

---

## 0. 定位：为什么它在最前面

产品口径（用户 10-09 定）：**上衣首先是合身**，大多数人衣服不合适；合身要"以人的身体为准"有一套公式或标准，先确定合身，其次才是服装与肤色。

所以处方分成三层，顺序固定，且**三层各自出结论、不许合成一个分**：

| 层 | 回答什么 | 依据硬度 |
|---|---|---|
| 第 0 层 合身（本文件） | 你该选哪个号型、成衣胸围做到几 cm、四道部位该看哪几个数 | 号型与测量方法有现行国标（A 档，数值为公开转录＝【二手】）；容差是 C 档手拍 |
| 第 1 层 修形（`topFromBody.js` 六轴） | 上衣往哪一侧修比例（加肩／别硬收腰／条纹…） | 方向 B 档，刻度与权重 C 档手拍 |
| 第 2 层 颜色（同上 `colour` 段） | 哪些颜色与你的肤色在色度学上分得开 | 公式 A 档，权重 C 档手拍 |

**第 0 层与第 1 层的结论可以相反，这是正确的，不许调和。** 例：按号型你该穿 165/88A（合身），但按感知研究你这个 BMI 档穿松 10cm 被评更瘦（`topFitBody.js` 的 `ease_windows`）。两者都写出来，选哪个是用户的决定。混成一个分数就是编造。

## 1. 输入规范

一律走 `profileEnricher` 那套字段名，单位 **cm / kg**，数值型。**没有的字段不许兜底**：非正数、非有限、空串一律当"没量"（沿用 `topFitBody.js` 的 `meas()`）。

| 字段 | 中文 | 本层用途 | 没量怎么办 |
|---|---|---|---|
| `height` | 身高 | 定"号"（5cm 一档） | 号出不了 ⇒ 整层挡住 |
| `bust` | 净胸围（过胸最丰处水平一周） | 定"型"（4cm 一档）＋ 算成衣胸围目标 | 型与成衣胸围出不了 ⇒ 整层挡住 |
| `waist` | 净腰围（腰最细处水平一周） | 定体型 Y/A/B/C（胸腰差） | 体型位不出，号型只给"号/型"，并写明缺腰围 |
| `shoulder` | 净肩宽（两肩点直线宽） | 肩缝落点那道判据的目标区间 | 那道判据不出（其余照出） |
| `gender` | 性别 | Y/A/B/C 切点分男女 | 未知 ⇒ 体型位不出，不猜 |

⛔ **本项目里没有、因此这一层永远不判的东西**（写出来是为了不许被当成漏实现）：袖长、袖笼弧长、腰节长/背长、领围、成衣实际尺码。衣柜表 `user_wardrobe` 实测无 `size`/成品尺寸列（列清单见 `db/schema.sql`），所以"这件到底合不合身"目前**判不了**，只能告诉你"去买胸围 X~Y cm 的那件"。

**采集侧现状（10-09 第七轮现量）**：上表五个输入**两种模式都收得到**了——个人深度模式一直在收胸/腰（`PersonalProfileForm.tsx:495-496`）；门店那张表本轮加了**净胸围、净腰围**两格（`CustomerForm.tsx`，五格两列：身高／体重／净胸围／净腰围／肩宽，仍全标"选填"）。写路径一起验了：门店提交后 `customer_sessions.profile_data` 实测 `{"height":165,"weight":62,"bust":92,"waist":84,"shoulder":39}`。门店侧**不收臀围与腿长**⇒胸臀差那一路和腿身比那轴在门店模式下缺席（属第 1 层，不影响本层）；后端字段白名单 `profileArchive.js:58-59` 早就有 `bust→bust_cm`、`waist→waist_cm`，这轮**没动后端**。

## 2. 号型推导（GB/T 1335）

```
号 = round(height / 5) × 5                       身高按 5cm 分档
型 = round(bust / 4) × 4                         胸围按 4cm 分档（上装）
落差 = 净胸围 − 净腰围                            上装的体型分类依据
体型 = Y / A / B / C，按性别的胸腰差区间取档（见下表）
标注 = `${号}/${型}${体型}`                       例：165/88A
```

胸腰差分档（流传值，【二手】）：

| 体型 | 男（cm） | 女（cm） | 含义 |
|---|---|---|---|
| Y | 22~17 | 24~19 | 瘦体（胸腰差大） |
| A | 16~12 | 18~14 | 正常体 |
| B | 11~7 | 13~9 | 偏胖体 |
| C | 6~2 | 8~4 | 胖体 |

**四条诚实规则**：

1. 落差落在两档之间的空隙（如男 16.5）⇒ 不四舍五入进档，返回"不整"并说明。区间按上表逐字实现，边界包含在内。
2. 落差 **< C 档下界**（男 <2、女 <4）或为负（腰围≥胸围）⇒ **不给体型位**，输出"胸腰差 x cm 低于 C 档下界 ⇒ 号型的体型位不替你编"。这一条不许偷偷塞进 C。
3. 号或型超出常见档系范围（号 145~190、型 72~120）⇒ 仍给就近档，但**必须标注"就近换算，超出国标常用档系"**，不许显示成标准号。
4. 分档数值来自公开转录（`docs/依据/01` 第 33 行），标准原文（openstd 该条不提供免费文本阅读）**未逐字核对** ⇒ 一切对外展示必须带"号型分档值取自公开转录，正式引用前需购 GB/T 1335.1/.2 文本复核"。可以说"按 GB/T 1335 号型系列的逻辑"，**不可以**说"按国标计算得出你的体型"。

## 3. 四道部位判据

每道判据的输出结构固定：`{key, name_cn, verdict, target, why, tier, missing_input}`。
`verdict ∈ 可给目标值 / 判不了 / 不适用`，**本层没有"你这件不合格"** —— 因为没有成衣实测数可判。

| # | 部位 | 判据 | 目标值算法 | 档位 |
|---|---|---|---|---|
| 1 | 胸围松量 | 成衣胸围 − 净胸围 应落在松量窗口 | `[净胸围+lo, 净胸围+hi]`，`lo/hi` **复用** `topFitBody.BODY_REF.ease_windows`（按 BMI 取档）⇒ 全局只有一套松量口径 | 窗口 B−（Liu 2006 n=9 / Sakata 2020 n=20）＋BMI 分档 C |
| 2 | 肩缝落点 | 成品肩宽 vs 净肩宽 | 正肩：`[净肩宽−1.5, 净肩宽+1.5]`；落肩款式：`≥ 净肩宽+3`；无肩宽 ⇒ 判不了 | **C 档手拍**（±1.5/+3 是版型行业经验，无标准无论文） |
| 3 | 衣长／腰节 | 衣长下摆落在你想让人看到的腰线位置 | **无腰节长字段 ⇒ 判不了**；只出"该看哪两个数"的说明，不给数 | — |
| 4 | 袖长／袖笼 | 袖长自肩点至腕、袖笼应合臂根 | **无字段且衣柜表无成品尺寸 ⇒ 判不了**，只列"需要补的字段" | — |

补充判据（不是第 5 道，写进第 1 道的 `why` 里）：**针织与机织的放松量不是同一套数** —— 弹性面料可取窗口下限，无弹机织取上限。项目里没有面料弹性字段 ⇒ 只在话术里提示，不进算法。

## 4. 缺测就挡在门口（这一层的硬规则）

`height` 或 `bust` 没量 ⇒ `fit.present = false`，且**不输出任何目标值**，只出：

- `blocking`：一句"这一层判不了，先量这两处"，点名缺的是哪个数；
- `measure_guide`：怎么量（部位、软尺走法、读数时机），依据 GB/T 16160-2017《服装用人体测量的尺寸定义与方法》——该标准只管**怎么量**，不管量到多少算好看；
- 前端必须显示这一段，不许显示空白判据或"建议咨询专业人士"。

理由：现在缺胸腰臀只是静悄悄少出几轴，顾客看到的是"算法不行"。合身既然是第一层，缺输入就得把"先量身体"这件事明确交回给用户。

## 5. 输出结构

```js
fit = {
  present: true,                       // false 时只有 blocking + measure_guide
  size_label: '165/88A',
  size: { 号: 165, 型: 88, 体型: 'A', 体型中文: '正常体' },
  size_scope: 'standard' | 'near',     // near ⇒ 超常用档系，就近换算
  drop: 24,                            // 胸腰差 cm；null ⇒ 没量腰围
  target_finished_bust: [94, 99],      // 净胸围 + 松量窗口
  ease_window_cm: [2, 7],
  checks: [ {key, name_cn, verdict, target, why, tier, missing_input} ×4 ],
  measure_guide: [ '…', '…' ],
  note: '这一层只回答尺寸合不合，不回答好不好看…',
  evidence: 'GB/T 1335.1-2008／1335.2-2008（现行，分档数值【二手·需购文本复核】）＋ GB/T 16160-2017（测量方法）＋ C 档手拍容差',
}
```

写入位置：`topSpec(person).fit`（第 0 段，排在 `axes` 前）。文字报告与 `TopSpecCard` 同顺序渲染，颜色段挪到最后。

## 6. 对外措辞（可以说／不可以说）

| 可以说 | 不可以说 |
|---|---|
| "按 GB/T 1335 号型系列的逻辑换算出号与型" | "按国标计算得出你该穿几号"（分档数值未对原文核对） |
| "号型只管尺寸分档，不含好不好看的判据"（`docs/依据/01` 第 35 行原话） | "合身就是好看" |
| "松量窗口来自两项公开研究（n=9／n=20，均低于 ITU-T P.910 的 ≥24 被试线）" | "科学证明这样穿显瘦" |
| "肩缝容差 ±1.5cm 是我们手拍的版型经验值，标定中" | 把 ±1.5 说成行业标准 |
| "同一号不同品牌成品尺寸实测可差 2~4cm，这一层管不了" | 假装号型跨品牌可比 |

## 7. 已知缺口（不许当已做完）

1. 分档数值【二手】：要升级到【官方原文】必须买到 GB/T 1335.1/.2 文本逐字核对（openstd 那条不给读）。
2. 没有成衣尺码通道：衣柜表无 `size`/成品尺寸列 ⇒ "你这件合不合"永远判不了，只能出"该买哪一档"。要真判，得在录入表加"成品胸围/肩宽/袖长"三格（`08` §9.4 第 1 步的录入表仍未做）。
3. 腰节长、袖长、袖笼、领围无字段 ⇒ 第 3、4 道判据长期是"判不了"。
4. 松量窗口按 BMI 分档来自 Liu 2006（**n=9 中国男性、白 T 一件**），套到衬衫/针织上是外推；已在 `topFitBody.js` 注释与本文件档位栏写明。
5. 本层全部数值容差未经标定，标定协议见 `08` §9.3（≥24 被试 + Thurstone/Bradley-Terry）。
