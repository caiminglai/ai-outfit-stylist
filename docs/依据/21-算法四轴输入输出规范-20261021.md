### 2 「肤色／肉色／腮红」元词黑名单

### 3 借本组配色第一色（你拍的板）

- 位置：`recommendEngine.js:553` 取到 `topText` 之后、`:580` 调 `colorFit` 之前。**只在规则候选那一路**，衣橱那一路（`:687` 起）不动——它有实测色。
- 触发条件（三条全满足才借，⛔ 任一不满足就当没这回事）：
  1. 上衣那一格**认不出任何具体色值**（`_resolveDetailed` 无 hex；只有明度档也算"认不出具体色"，但⛔ 覆盖它原有的明度档口径——借到具体色时以具体色为准，`basis` 记两笔）；
  2. 同一条 recommendation 的 `color_combo`（或兜底那条的 `outfit_color`）**认得出至少一个具体色**；
  3. 借的是那一个色**在串里的位置**，⛔ 不是"挑一个最好看的"。
- 出处字段（新增，全部可拆账）：`color_basis_source` = `'top_text' | 'combo_first' | 'lightness_band'`；借来时另记 `color_borrowed_from` = 串原文、`color_borrowed_position` = 第几个（从 1 数）。
- 降权：`rankDims`（`:668`）里 color 那一维的 `weight` 在借色时乘 `COLOR_BORROW_WEIGHT = 0.5`（C 档，见 §六），在场判据不变（分数照算、权重照归一）。⛔ 不在 `colorFit` 的分数里再乘一次——同一件事两层各折一次是本项目反复清扫的病灶（`:681-685` 那条禁令）。

- ⛔ 不做的事：不因为借色而给"没写色的上衣"编一个默认色；串里也没色 ⇒ 这一维继续缺席，照旧吃 `RANK_ALGO_ABSENCE_PENALTY`（`:615`）。

- 面料词 → `FABRIC_WEIGHT_VALUES`（`topFitBody.js:471` 的 `薄/中/厚`）：毛皮类（羊毛／羊绒／毛呢／羽绒／灯芯绒／大衣／厚重／厚实）→ 厚；轻薄类（雪纺／真丝／丝绸／缎／蕾丝／薄纱／冰丝／莫代尔／亚麻／棉麻／轻薄）→ 薄；中间类（针织／卫衣／牛仔／帆布／皮革／醋酸／天丝／纯棉／硬挺／挺括）→ 中。⚠️ "挺括／硬挺"在库里 5/5 行，说的是手感不是克重 ⇒ 这两个词**只当廓形线索**（§三·2 的款式词），⛔ 不进厚薄档（列进 §七 待裁）。

### 3 判据与"判不出"

1. 命中 0 档 ⇒ `null`。调用方按"这一维没数据"处理（与改前逐条相同）。
2. 命中 ≥2 档 ⇒ `null`。⛔ 取第一个命中词、⛔ 多数表决、⛔ 按词长优先。现量代价：`bottom_style` 有 38 行（24.2%）会走这条分支。
3. 命中恰好 1 档 ⇒ 出 `{fit_type, words:[命中词], basis:'inferred_from_text'}`。
4. ⛔ 只看款式词与面料词这些**离散档**，绝不在这层估任何 cm 级数值——那是 10-19 第二阶段废除掉的"中文猜测"，本层不复辟。

### 4 接线（复用现成公式，不建第二条尺子）
