## 二、实现细节（四步各干了什么，以及为什么是这个形状）

### 2.1 一b 反馈解绑：加一档，而不是改两档的语义

改前的问题是**语义耦合**：星级控件早就画在报告页上了，但提交被 `if (signal || …)` 挡在👍/👎后面 ⇒ 用户只打星＝什么都不发 ⇒ `feedback_events` 0 行。本轮加的是**第三档** `rated`，两档老语义一个字没动。三条硬约束：

1. `rated` **必须至少带一把星**才收（`recommend.js:169`），否则它会变成"有一行、什么信息都没有"的噪声，而 `feedback_events` 的 `UNIQUE(user_id, group_id)`（`schema.sql:320`，本轮没漂）还会把这个人在这条规则上的正负表态顶掉。
2. `rated` **不进好评／差评计数**：`recountRules` 的 SQL 只数 `signal='useful'`（`ruleFeedback.js:90`）⇒ 后台"好评率"不会被只打星的人稀释。这条由 `ruleFeedbackStars.test.js` 钉住，防以后有人图省事把 `rated` 数成好评。
3. 星级越界**说破**（400），不静默抹成"没打"——与 `16` §一·1.1 的 undefined＝不动／null＝清空同一把尺子。

### 2.2 一c 日记后端：**一列没加**，只是把通路补全

`schema.sql:385-396` 里 `wardrobe_outfits` 本来就有 `user_id` 与 `rating`，改前的 INSERT 只写 6 列（这两格压根没进列清单）⇒ 记了也不知道是谁记的、星级永远为空。本轮改的是**写入口**，不是表。四个口径必须记在这儿：

- **归属＝session ∪ user 两条口径取并集**（`wardrobe.js:872` 用 `outfitOwnershipFilter`）。理由：日记的价值在"我自己回头能看见"，换设备／清了 session 不该把前面记的弄丢。
- **场合只认受控词，词表现从 `rule_conditions WHERE field='occasion'` 取**（`:120`），**不写死**——库里改了词，前端立刻跟着改；表外词 **400 说破**，不许静默落 NULL（那是 10-13 现量过的"抹成 NULL＋前端弹已保存"）。词表为空时回 400「场合词表还没建好，这一格先留空」。
- **PUT 的字段级契约**：`undefined＝这次不动／null＝明确清空`；收到畸形值 ⇒ 400 **且旧行一个字节不改**。
- **DELETE 只删 `wardrobe_outfits` 那一行，绝不动 `user_wardrobe`**；越权一律 **404 不 403**（403 等于把"这行存在"白送给脚本）。

### 2.3 一d 日记前端：入口放衣橱页，且把话说小

组件里那行引子逐字是「记下"今天这么穿了一身"，系统只按你自己记的这些把常穿的色系和场合稍微排前一点。**这不是机器学习，样本不够时它一个字也不改你的排序**」。这条是刻意的：`16` §八 第 5 条不许我把运营激励写进代码，而"自动学习"这种词一进前端文案就成了对外夸大。表单只有名称／场合／季节／选衣／一星／备注六样，都可选（`item_ids` 与 `name` 除外）。

### 2.4 一e 偏好画像：五轴、两轴进乘子、幅度钉死在 ±5%

`buildPreference(who)` 读两路原料（日记 `wardrobe_outfits` ＋ 推荐卡星级 `feedback_events`），出五轴：`color_family`／`fit_type`（**只有这两轴进乘子**）、`occasion`／`season`／`rating`（只出账、不进乘子）。参数全是 **C 档手拍**：`MIN_SAMPLES=3`（`:37`）、`FACTOR 0.95~1.05`、`LIFT_TOP +0.02 / LIFT_SEEN 0 / LIFT_UNSEEN −0.01`（`:49` `MULTIPLIER_AXES`）。三条设计取舍：

- **一套穿搭里同一色族只记一票**（上下都蓝≠两票），衣服后来被删了那一票**不补**（缺测不出分）。
- **样本不足 ⇒ `factor` 恰好等于 1**，不是 0.999、不是"轻微下降"；`buildPreference(null)` 也合法（默认参数只对 `undefined` 生效，这一层没挡就是 `routes` 里一条 500）。
- **⛔ 不输出置信度、不输出星级、不做"因为你喜欢所以合适"这类话**；对外只许说"按你自己记的这些稍微排前一点"。⚠️ 它**不是**协同过滤——协同过滤要别人，这一层只有你自己。

### 2.5 测试：三套共 39 个新增断言

`wearPreference.test.js` **13/13**（新 517 行）——核心那条是"零样本零影响"：不传身份 vs 传一个查不到行的身份 ⇒ Top 8 逐条相同、乘子恰好 1；另钉"无身份不发一条 SQL"（`db.prepare` 被替身顶掉，一被调用就抛）。`wardrobeDiaryRoutes.test.js` **11/11**（新 287 行，起临时 `express()` 实例真发 HTTP，六件事全是行为断言）。`ruleFeedbackStars.test.js` **15/15**（改前 11）。三套都用内存库替身（`require.cache` 顶掉 `../db/init`），**没打开过活库**。
